# NextStep

先看下一步，需要时再展开全图。

一个通用 Agent Skill，配套原创离线行动图工具。Agent 把用户认可的任务整理为小步骤，工具生成独立 HTML，明确显示下一步动作、完成标准和依赖。你可以标记完成、记录阻塞、导出进度，下次接着做。

[English](README.md)

## 先试虚构示例

浏览器进度损坏后，新的操作不会覆盖原数据。先导出当前内存中的进度，再确认导入有效文件，才会恢复保存；取消导入会保留原数据。

计划输入会拒绝重复的 JSON 字段，包括步骤中的嵌套字段；拒绝后不会生成行动图。

下载仓库后，直接用浏览器打开 `examples/study.html`。无需账号、服务器或网络。默认突出一个可开始的动作；展开后保留全部步骤及文字说明，窄屏以文字列表代替 SVG。

生成新图需要 Python 3.10 及以上版本，无运行时第三方依赖：

```sh
git clone https://github.com/Amossse/nextstep.git
cd nextstep
python scripts/nextstep.py validate examples/study.json
python scripts/nextstep.py render examples/study.json --out ../my-action-map.html
```

打开输出文件即可。已有文件不会覆盖，请换一个文件名。路径含符号链接时会拒绝执行，需要使用物理路径。

## 安装 Skill

安装资源先复制到同级暂存目录，全部成功后再发布最终目录。复制失败会清理暂存内容，不留下半套最终安装；解决读写错误后可重试，父目录可能保留。已有目标仍会被拒绝，不会自动删除用户文件；这不是防御恶意文件系统竞态的沙箱。

选择宿主支持的 Skill 目录，指定一个尚不存在、名称为 `nextstep` 的文件夹：

```sh
python scripts/nextstep.py install --to /physical/path/to/skills/nextstep
```

安装器只复制 Skill、脚本、界面资源和格式说明，不修改全局指令。刷新宿主的 Skill 发现后，调用 `$nextstep` 或宿主支持的对应命令。需要本地 Python 和文件权限，不保证所有 Agent 自动发现。

可以对 Agent 说：

> 使用 nextstep，把这份任务整理成行动图。先提出一个能开始的小动作，保留依赖和不确定性，给出完成标准。只保存在本机，不代我执行。

Agent 负责理解和提出计划，脚本只校验 JSON 并画图，不能独立理解任意文档。格式详见 [format.md](references/format.md)。发布开源项目不代表允许公开用户后来输入的计划。

## 中断后接着做

点击完成后才解锁依赖该步骤的动作；独立步骤按计划顺序选择。受阻时填写原因，解除后继续。完成标记是用户记录，不能当作 Agent 已验证实际结果。

浏览器可能无法长期保存本地文件的进度。重要进度请导出 JSON；换浏览器或移动文件后，打开同一计划并导入。导入会校验计划指纹、状态和依赖，并在替换前询问。修改计划会生成新指纹，首版不迁移旧进度。撤销完成时，需先从末端撤销已完成的后续步骤。

不使用颜色作为唯一状态提示，提供原生键盘控件、焦点提示和完整文字说明。关闭 JavaScript 后仍可阅读步骤，但不能操作进度。无自动执行、定时提醒、云同步或账号体系，也不诊断或治疗 ADHD。

## 隐私与边界

数据流为“用户认可的材料 → 宿主 Agent → JSON → 本地 Python → HTML/SVG → 用户进度”。最多 12 步，每步最多 3 个前置依赖；较大任务需拆分，不会悄悄截掉内容。

HTML 包含完整计划，进度导出包含阻塞备注。真实内容请保存在仓库之外，不要直接提交或上传。工具没有联网或模型调用，但宿主模型仍可能按提供方政策处理材料。没有加密、身份认证或可靠的秘密检测器；浏览器存储也不是跨文件的隐私隔离机制。

输入文本不会作为 HTML 或命令执行。工具校验结构、大小与依赖环路，输出限制网络连接，并拒绝覆盖已有文件。新输出在支持的 POSIX 系统使用受限权限，Windows 需管理目录 ACL。这些措施不等于操作系统沙箱，也不保证清除浏览器备份或其他副本。

## 验证与开源

暂存输出流创建失败时，工具会先关闭尚未移交的文件描述符，再清理暂存文件。回归通过注入异常核对描述符已关闭、没有发布输出；不代表所有读写故障或进程崩溃均已覆盖。

计划文件必须是 UTF-8 JSON，可带 UTF-8 BOM；不再自动识别 UTF-16/32。请明确转换为 UTF-8，编码被拒绝时不会创建输出文件。浏览器进度导入仍使用原有的严格 UTF-8 规则。

计划输入必须是普通文件。POSIX 管道通过非阻塞打开后拒绝，不等待写入方，也不生成输出；请先保存完整的 UTF-8 JSON 文件。Windows 运行描述符类型回归，跳过 POSIX 管道案例。此检查不是操作系统沙箱。

读取侧新增故障注入，检查拒绝文件类型或创建读取流失败后，实际打开的描述符已关闭，随后仍能正常读取计划。此项补齐错误路径的覆盖，运行时代码未改，不代表所有文件系统故障均已验证。

Chromium 回归增加了双前置依赖场景：一个独立分支受阻时，完成另一个分支仍不能解锁汇合步骤；恢复、撤销与刷新后，依赖约束和另一分支的完成记录保持正确。运行时代码未改，未据此测量真实用户效果。

Chromium 交互检查还覆盖独立的虚构英文计划，包括键盘完成、必填阻塞备注、刷新、导出导入及最终完成。它验证英文界面的交互分支，不证明真实用户效果或所有浏览器的兼容性。

```sh
python -m unittest discover -s tests -v
```

另有 Chromium 交互检查，安装方法见英文 README。验证只用虚构数据，覆盖完成、阻塞、恢复、进度导入导出和恶意文本。尚未通过真实用户对照测试证明更容易开始或提高效率。

新增竞争时序回归：渲染已写入暂存文件、尚未发布时，模拟另一个进程创建目标文件。CLI 必须拒绝替换，保留对方内容与原计划，并清理自身暂存文件。此项只补齐防覆盖边界的测试，运行时代码未改，也不承诺隔离恶意本地进程。

存储失败场景还会导出进度，在独立浏览器上下文导入并刷新，核对能否继续；这不保证所有浏览器都能持久保存本地文件的进度。
进度 JSON 必须是有效的 UTF-8。解码失败时不会请求替换确认，也不会修改原进度；请重新导出有效备份，不要猜测损坏字节的原文。
连续选择进度文件时，以最后一次选择为准，较早但尚未读完的文件不会再替换进度；取消确认或导入无效文件仍会保留当前状态。
